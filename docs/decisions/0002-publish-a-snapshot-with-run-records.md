# ADR 0002: Publish a snapshot, and commit run records instead of raw reviews

**Status:** Accepted · **Date:** 2026-10-07 · **Supersedes:** none

## Context

The repository becomes public open source once the proof of concept is pushed. Its only contributor is the owner. The remote holds one commit, a one-line README.

The local history held the raw output of every review run in `docs/reviews/`, the folder now named `docs/records/`: verbatim reviewer reports, findings registers with reproduction details, and readiness reports. These named Claude Code sessions and Codex threads, costs, and local paths. A snapshot of the tree would still publish those files, and deleting them later would leave them in the published history.

Public review discussion is normal in open source, but it lives in the review tool, not in the source tree. Raw coding-agent output has no convention for publication. The repository already keeps raw live-model output in the git-ignored `observations/`, and commits only sanitized evidence.

## Decision

The repository is published as one snapshot commit on top of the remote's initial commit. The development history before it is not published; the owner keeps it in a git bundle outside the repository.

Each workflow run commits one run record to `docs/records/`, generated by `scripts/run_record.py` in [the run-record format](../templates/run-record.md). A run record summarizes the gates, the reviewers with their tools and models, each finding with its disposition, the owner's decisions, and what remains unverified. It contains no verbatim reviewer output, session or thread ids, costs, or local paths.

Raw output stays local. The raw reports, the findings register, and the readiness output stay in `.reviews/<run>/`, which `.gitignore` excludes, and `scripts/readiness.py` reads them there.

A run record lists the SHA-256 of each raw report, so the holder of the raw files can show that the summary matches them. It also names the reviewed commits.

## Alternatives considered

- Commit raw reports, as before. This keeps a full audit trail, but it publishes session metadata and reproduction steps for unfixed issues. It puts stale model-written text where other people's agents read it. It also lets later reviewers read earlier conclusions through git history.
- Rewrite the history to drop the raw reports, or squash the branch. Either keeps more history, but every cited commit changes, and the result still needs the same cleanup. A fresh snapshot is simpler for a proof of concept with one contributor.
- Delete raw reports after each run. Then nobody can check the evidence again. An earlier closeout already had to rebuild its reports from session transcripts and temporary files.
- Keep the reports as CI artifacts. They expire, and the reviews run locally on the owner's accounts, not in CI.

## Consequences

- Raw reports exist only on the owner's machine. `git clean -x` deletes `.reviews/`, so back it up.
- A reader of the public repository cannot verify that a review took place: a run record is a summary written by the coordinator, not proof. Nothing local authenticates a review report either, and a pull request cannot supply evidence to the machine that runs the readiness check. The owner accepted this limit for the local, single-user workflow on 2026-10-07.
- Pull requests can still change `.claude/`, `.agents/`, `AGENTS.md`, and `scripts/`, which run on or instruct the owner's tools. Review them as code.
