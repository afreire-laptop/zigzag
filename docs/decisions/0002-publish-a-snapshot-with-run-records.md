# ADR 0002: Publish a snapshot, and commit run records instead of raw reviews

**Status:** Accepted · **Date:** 2026-10-07 · **Supersedes:** none

## Context

The repository becomes public open source once the proof of concept is pushed. Its only contributor is the owner. The remote holds one commit, a one-line README.

The local history held the raw output of every review run in `docs/reviews/`, the folder now named `docs/records/`: verbatim reviewer reports, findings registers with reproduction details, and readiness reports. These named Claude Code sessions and Codex threads, costs, and local paths. A snapshot of the tree would still publish those files, and a later deletion would leave them in the published history.

Public review discussion is normal in open source, but it lives in the review tool, not in the source tree. Raw coding-agent output has no convention for publication. The repository already keeps raw live-model output in the git-ignored `observations/`, and commits only sanitized evidence.

## Decision

- **Publication.** The repository is published as one snapshot commit on top of the remote's initial commit. The development history before it is not published. The owner keeps it in a git bundle outside the repository.
- **Run records.** Each workflow run commits one run record to `docs/records/`, generated by `scripts/run_record.py` in [the run-record format](../templates/run-record.md). It summarizes the gates, the reviewers with their tools and models, each finding with its disposition, the owner's decisions, and what remains unverified. It contains no verbatim reviewer output, session or thread ids, costs, or local paths.
- **Raw output stays local.** Raw reports, the findings register, and the readiness output stay in `.reviews/<run>/`, which `.gitignore` excludes. `scripts/readiness.py` reads them there.
- **Binding.** A run record lists the SHA-256 of each raw report, so the holder of the raw files can show that the summary matches them. It names the reviewed commits. The two runs before publication reviewed commits that are not published, so their records give git tree hashes of the reviewed folders instead, which anyone can compare with the published tree.

## Alternatives considered

- **Commit raw reports, as before.** This is a full audit trail, but it publishes session metadata and reproduction steps for unfixed issues. It puts stale model-written text where other people's agents read it. It also lets later reviewers read earlier conclusions through git history.
- **Rewrite the history to drop the raw reports, or squash the branch.** These keep more history, but every cited commit changes, and the result still needs the same cleanup. A fresh snapshot is simpler for a proof of concept with one contributor.
- **Delete raw reports after each run.** Then nobody can check the evidence again. The migration closeout already had to rebuild its reports from session transcripts and temporary files.
- **CI artifacts.** They expire, and the reviews run locally on the owner's accounts, not in CI.

## Consequences

- The run records for the migration and the agent workflow cite no commits. Their commit references are in the archived history only.
- Raw reports exist only on the owner's machine. `git clean -x` deletes `.reviews/`, so back it up.
- A reader of the public repository cannot verify that a review took place. A run record is a summary written by the coordinator, not proof. Finding X2 still applies, now in its local scope, because a pull request cannot supply evidence to the machine that runs the readiness check. The owner accepted it on 2026-10-07.
- Pull requests can still change `.claude/`, `.agents/`, `AGENTS.md`, and `scripts/`, which run on or instruct the owner's tools. Review them as code.
